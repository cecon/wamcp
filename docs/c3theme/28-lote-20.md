# Lote 20 — Indicador de digitação, filtros e menu da conversa no C3Theme

> **Objetivo:** fechar o entorno da thread migrando o indicador de digitação, as ações de filtro/views e o menu “mais ações” da conversa, incluindo o diálogo de exclusão. Resultado: **48 de 154 telas migradas (31%)**, 220 testes verdes em duas execuções.

> A régua passou de 153 para 154 telas porque o `ConversationFilters` deixou de ser “arquivo sem interface contável” ao importar MUI — o total é recalculado pelo script, não é tela nova.

---

## 1. O que mudou

| Peça                                                                         | Migrado                                                                                                                                | Continua no app                           |
| ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| [TypingIndicator](../../src/agent/conversations/TypingIndicator.tsx)         | `Stack` com `role="status"`, bolinhas animadas e texto “está digitando/gravando áudio…”                                                | —                                         |
| [ConversationFilters](../../src/agent/conversations/ConversationFilters.tsx) | “Filtrar conversas” (`IconButton`), “Limpar filtros” (`Button`) e as views salvas                                                      | `FilterModal`/`SaveViewButton`/`ViewMenu` |
| [ConversationMenu](../../src/agent/conversations/ConversationMenu.tsx)       | “Mais ações” em `IconButton` + `Menu`/`MenuItem` (não lida, silenciar/reativar, transcrição, excluir) e **`ActionDialog`** de exclusão | `download`/`http`                         |
| [ConversationMenu](../../src/agent/conversations/ConversationMenu.tsx)       | erro de exclusão via `error` do `ActionDialog` (com `role="alert"`), `loading` durante o DELETE                                        | —                                         |

O diálogo de exclusão fica dentro de `C3Provider` (a thread não está sob o provider da página) e trata a promise: em erro mostra o alerta no diálogo sem fechar; em sucesso chama `onDeleted`.

## 2. Contratos preservados sem edição de teste

`role="status"` com “João Cliente está digitando…” / “Maria está gravando áudio…”; “Filtrar conversas”, “Limpar filtros”; “Mais ações” com itens “Marcar como não lida”, “Silenciar conversa”/“Reativar notificações”, “Baixar transcrição”, “Excluir conversa” (oculto para agentes); diálogo “Excluir conversa” com botão “Excluir” e **`role="alert"`** “Somente administradores…” quando a API recusa.

## 4. Achado

**`ActionDialog` precisa receber `error`/`loading` para reproduzir o comportamento antigo.** O `ConfirmModal` do app mostrava o erro da API dentro do diálogo (`role="alert"`); ao trocar pelo `ActionDialog`, a promise de exclusão passou a ser tratada no componente e o erro vai para a prop `error` — o teste que simula 403 continuou válido.
